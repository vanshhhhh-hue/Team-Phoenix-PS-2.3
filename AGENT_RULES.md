# Coding rules
1. One repository: https://github.com/vanshhhhh-hue/Team-Phoenix-PS-2.3.git; one PC, one owner, sequential work.
2. Start by reading applicable repository instructions, this file, PROJECT.md, TASKS.md and HANDOFF.md.
3. Read API_CONTRACT.md before changing application operations, state or data.
4. Run `git status` and `git log -5 --oneline`; an unborn branch has no log yet.
5. Inspect the current task and run its existing check when available.
6. Continue HANDOFF.md's next exact step. Preserve unrelated and uncommitted work.
7. Complete one connected user flow at a time across UI and domain code. No separate integration phase.
8. Use the existing checkout; never create another frontend/backend repository or clone.
9. Product scope is the original AI Study Companion: uploads, adaptive quizzes, hints, flashcards and weak topics.
10. Use normal Python functions for named expressions; never eval or parse arbitrary equations.
11. Gemini may generate source-grounded content; deterministic code grades and schedules. Fall back locally on failure.
12. Support notes/PDF/syllabus uploads. Keep single-student local persistence; no accounts or Docker required.
13. Treat a misconception as a candidate rule, not a certain diagnosis. Numerical checks are not proofs.
14. Keep help use, immediate repair, transfer and delayed evidence separate.
15. Validate packs and imported progress before replacing any current state.
16. Keep credentials out of code, logs, exports and Git. Preserve safe .env.example.
17. Use PowerShell or cross-platform scripts. Python 3.14.6 is tested; retain the verified dependency pins.
18. Run meaningful task checks before DONE; record exact commands and observed results.
19. Keep only one task IN-PROGRESS. Update API_CONTRACT.md and callers with interface changes.
20. Commit only completed verified work using `T01: <completed behavior>` style messages.
21. Push meaningful checkpoints when access permits; report failures without claiming success.
22. Seven-hour implementation budget: checkpoint by hour three; freeze features at hour six.
23. Preserve the full uploaded-material journey first. The authored algebra lab is a supporting module.
24. Rewrite HANDOFF.md before stopping; never append a running transcript.
25. Never claim deployment, live AI, learning efficacy or diagnostic validity without evidence.
